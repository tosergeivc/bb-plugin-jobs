# bb-plugin-jobs

English version: [README.md](README.md).

Плагин bb: команда `bb jobs` запускает долгие команды (серверы, деплои, сборки) как фоновые задачи, которые не умирают вместе с ходом агента, ждёт готовности сервера и сообщает треду агента о завершении задачи.

## Зачем

Процессы, запущенные агентом через Bash, живут в дереве процессов bb. Провайдер агента завершает дерево своих процессов в конце хода (проверено: `nohup … &` и `setsid` не пережили конец хода). На Linux bb часто работает как `bb-app.service` с `KillMode=control-group`, и остановка или обновление сервиса убивает все процессы его cgroup.

## Как работает

- `server.ts` регистрирует CLI `bb jobs`. Команда выполняется на сервере bb и пересылает вызов host-entry на машину треда (thread → environment → hostId) или на `--machine`.
- `host.ts` работает в демоне bb на этой машине и вызывает `JobManager` из `jobs-core.ts`.
- Linux с user systemd: задача — transient unit `bbjob-<id>` (`systemd-run --user --collect`), своя cgroup вне `bb-app.service`. Остановка — `systemctl --user stop`, убивает всё дерево.
- Без user systemd (macOS): detached-процесс (новая сессия). Сохранённому PID плагин не доверяет: PID выдаются повторно. Процесс принадлежит задаче, если его командная строка точно совпадает с запуском файлов задачи (`runner.sh`, `exec.pl`, `command.sh`), если он их потомок, или если он в группе процессов команды, запущен не раньше задачи, а лидер группы — процесс задачи или уже завершился. Чужой процесс с тем же PID или `tail -f …/output.log` не считается задачей и не получает сигнал. Метку в окружении использовать нельзя: macOS скрывает окружение чужих процессов. Остановка — SIGTERM, через 10 с SIGKILL.
- `runner.sh` (своя копия в каталоге каждой задачи, не перезаписывается во время работы) переходит в каталог и передаёт управление `exec.pl`. Тот запускает команду в отдельной группе процессов, пишет вывод в `output.log` с ограничением размера, следит за `--timeout` и сразу после завершения команды записывает код выхода в файл `exit`. Задача не зависит от воркера bb.

## Команды

| Команда | Что делает |
|---------|------------|
| `bb jobs start --name <метка> -- <команда>` | Запуск в текущем каталоге; `--cwd`, `--env K=V`, `--timeout 30m`, `--log-max 50` (МиБ) |
| `bb jobs start … --ready-url URL` или `--ready-log REGEX` [`--ready-timeout 60s`] | Запуск и ожидание готовности: URL ответил 2xx или в логе появилась строка. Код 0 — готово, 1 — задача завершилась, 124 — ещё не готово (задача продолжает работать) |
| `bb jobs start … --notify` или `--notify-thread THREAD` | Когда задача завершится, отправить в вызвавший (или указанный) тред результат, команду, время и последние 2 КиБ вывода |
| `bb jobs ready <id> --url URL` или `--log REGEX` | Та же проверка готовности для уже запущенной задачи |
| `bb jobs list [--running]` | Задачи машины, новые первыми |
| `bb jobs status <id>` | Состояние, код выхода, путь к логу |
| `bb jobs logs <id> [--bytes N]` | Конец лога |
| `bb jobs wait <id> [--timeout 5m]` | Ждать завершения (до 10 мин за вызов) |
| `bb jobs stop <id>` | Остановить всё дерево процессов |
| `bb jobs prune --older-than 7d [--delete] [--dry-run]` | Перенести завершённые задачи старше срока в `archive/` плагина или удалить (`--delete`); работающие задачи не трогает |

Состояния: `running`, `exited`, `stopped`, `lost` (исчезла без кода выхода).

## Ограничения

- Ограничение лога и `--timeout` работают через perl (есть в macOS и Ubuntu). Без perl задача с `--timeout` завершается с кодом 125, остальные задачи пишут лог без ограничения.
- Лог хранит не больше двух `--log-max` (по умолчанию 50 МиБ): при превышении `output.log` становится `output.log.1`. `bb jobs logs` читает оба файла.
- В режиме detached дочерний процесс, который создал свою сессию или группу (`setsid`, многие демоны), находится, пока жив его родитель из задачи, но не после его завершения.
- Режим `detached` на Linux переживает конец хода, но не полную остановку `bb-app.service`.
- Задача наследует только PATH, HOME, USER, LOGNAME, SHELL, LANG, LC_ALL, TZ, SSH_AUTH_SOCK; остальное — через `--env`. При запуске из треда она также получает `BB_THREAD_ID` и `BB_PROJECT_ID`, а на машине треда ещё `BB_ENVIRONMENT_ID` и `BB_THREAD_STORAGE`.
- `--notify`: служба на сервере bb каждые 5 с проверяет отмеченные задачи и отправляет в тред одно сообщение (`queue-if-active`): активный тред получит его после текущего хода, неактивный начнёт новый ход. Доставка «хотя бы раз»: при остановке сервера в неудачный момент сообщение может прийти дважды. Задачи, остановленные через `bb jobs stop`, и удалённые треды не уведомляются.
- Linux: чтобы задачи жили после выхода пользователя из системы, нужен linger: `sudo loginctl enable-linger $USER`. `bb jobs start` предупреждает, если он выключен.
- Windows-машины не поддерживаются: `bb jobs start` отказывает с понятной ошибкой. WSL работает.
- Значения `--env` не хранятся на диске: они пишутся в `env.sh` (права 0600), задача читает и удаляет этот файл до запуска команды; если задача не стартовала, файл удаляет runner или следующий `status`/`list`. Значения остаются в окружении процесса задачи и проходят через командную строку `bb`, поэтому секрет лучше передавать как `--env TOKEN="$TOKEN"`. Саму команду не использовать для секретов: она хранится в `meta.json` и видна в `bb jobs status`.
- Каталоги завершённых задач не удаляются автоматически: для этого `bb jobs prune`. По умолчанию prune переносит их в `archive/`, место на диске при этом не освобождается; освобождает `--delete`.

## Похожие плагины

В маркетплейсе bb-community на 24.10.2026 есть [Terminal Jobs](https://github.com/ryanbbrown/bb-plugin-terminal-jobs) и [Shell tasks](https://github.com/ahkohd/bb-plugin-shell-tasks). Оба запускают команду из демона bb (`spawn` с `detached: true`), поэтому на Linux процесс остаётся в cgroup сервиса bb и завершается при его остановке или обновлении. `bb jobs` запускает задачу отдельным unit `systemd-run --user`, умеет ждать готовности, ограничивает лог и защищает от повторно выданных PID. У них есть то, чего нет у нас: панель в интерфейсе (Shell tasks), записи в SQLite с повтором уведомления (Terminal Jobs). Не ставьте несколько таких плагинов сразу: их навыки для агентов спорят.

## История версий

- **0.3.0** — `--notify` и `--notify-thread`; переменные `BB_*` в задаче; предупреждение о выключенном linger; отказ на Windows; служебные строки `[jobs]` всегда с новой строки; тесты переносимы на macOS; `PLUGIN_OVERVIEW.md`. Короткое описание больше не обещает переживать перезапуск bb: это не проверено.

- **0.2.0** — ожидание готовности (`--ready-url`, `--ready-log`, `bb jobs ready`); ограничение и ротация лога (`--log-max`); `bb jobs prune`; detached-задачи узнаются по командной строке запуска и группе процессов, чужой процесс с тем же PID не трогается; своя копия runner для каждой задачи; код выхода записывается, даже если оставшийся дочерний процесс держит вывод.
- **0.1.1** — значения `--env` не хранятся на диске.
- **0.1.0** — первая версия.
